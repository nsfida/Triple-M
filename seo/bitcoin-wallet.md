## Client-side Bitcoin wallet control beside your finance workspace

Monitor addresses without a private key, load spendable wallet access only when needed, select supported address types, send or receive Bitcoin and preserve transaction records while treating key material with appropriate caution.

## Inspect, receive and, where key access is loaded, send Bitcoin from a browser-controlled wallet workspace.

The Bitcoin module is intentionally different from an exchange account: it focuses on address and key-based wallet control inside the browser.

### Watch-only mode

Load an address for balance and history without introducing a private key.

### Private-key wallet

### Seed-based access

### Multiple address types

### Receive

## Keep address activity reviewable instead of treating the wallet as one opaque balance.

The module retrieves address activity and distinguishes received, sent and self/change-style movement where supported.

### Transaction history

Review transaction activity for the active address.

### Received totals

Inspect incoming activity and supported balance information.

### Sent activity

Review outgoing transactions from spendable wallet usage.

### Transaction PDFs

Generate PDF transaction records for individual history items.

### Wallet PDF

Export sensitive wallet material when explicitly requested, with strong security warnings.

### Bulk import tools

Load supported wallet files for broader address monitoring in authenticated usage.

## The private key is the wallet authority.

Bitcoin safety depends on protecting the secret material, not merely protecting the Triplem VIP login.

### Client-side handling

Sensitive signing and derivation workflows are performed in the browser.

### Watch-only separation

Use an address-only wallet when spending authority is unnecessary.

### Export caution

A wallet PDF or private key must be protected because possession can grant control over funds.

### Account security is separate

Authenticator, Smart PIN and session controls protect Triplem VIP access, but they do not change the cryptographic authority of a Bitcoin private key.

## Bitcoin wallet activity does not automatically become Accounting ERP entries.

Wallet cryptography and formal bookkeeping solve different problems.

Sending or receiving Bitcoin in the Bitcoin module does not automatically create Accounting journals or operational wallet transactions. If a Bitcoin movement must appear in formal books, record the appropriate accounting effect separately with the organization’s chosen valuation and accounting policy.
